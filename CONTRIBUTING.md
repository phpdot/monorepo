# Contributing

All development happens in this repository. The per-package repositories are read-only mirrors
generated by CI — pull requests and issues there cannot be acted on.

- One package per directory under `packages/`, each with its own `composer.json`, `src/`, `tests/`,
  `LICENSE`, and `README.md`.
- `composer check` must pass before any push: tests, PHPStan (level max, strict), code style.
  Start the service stack first (`docker compose up -d`) — the root phpunit.xml fails on skipped
  tests, so a down service fails the run rather than silently skipping its integration suite.
- To run a single package's tests from the monorepo root:
  `vendor/bin/phpunit -c packages/<name>/phpunit.xml --bootstrap vendor/autoload.php`
- Cross-package changes are one commit here — never coordinate across mirrors.
- Commit authorship is preserved into the mirrors; write commits you want public.

## Conventions

The tree's standards, written down. CI enforces the mechanical ones (style, static analysis,
manifest hygiene, README tables); the rest are the house rules every new file follows.

### Source

- Every file opens with `declare(strict_types=1);`, then a file-level docblock above the
  namespace: what the class is for (rationale, not restatement), `@author`, `@license MIT`.
  Explanations live in docblocks — no inline `//` comments in method bodies.
- Classes are `final` by default. The only open classes are abstract bases, package base
  exceptions, and deliberate extension points that shipped subclasses actually use.
- Value and config objects are `final readonly class` with public promoted properties and
  named-argument construction; services promote `private readonly` collaborators. Optional
  collaborators default via new-in-initializer.
- Nullable types are spelled `T|null`, never `?T` (enforced by the fixer).
- PHPStan level max + strict rules is the floor: array shapes, `list<>`, `class-string<T>`,
  and `@template` generics are part of the API, not decoration.
- Interfaces are suffixed `*Interface` and live in the package's `Contract/` directory —
  except cross-package contracts, which live in `phpdot/contracts`, and deliberate marker
  interfaces (the contracts DTO family), which carry bare role names. Octal literals are
  spelled `0oNNN`.

### Exceptions

- Each package defines an open base `class <Domain>Exception extends RuntimeException` in
  `src/Exception/`, with `final` leaves (named static constructors where a failure carries
  context). Every throw in the package goes through the hierarchy — no bare SPL throws.
- Implement the spec interfaces where a PSR defines them (PSR-11's container interfaces,
  PSR-16's cache interfaces).
- Third-party libraries are fenced behind one boundary class that translates every foreign
  exception; no vendor exception type leaks past it.
- bun, filesystem, and sheets predate this charter with marker-interface hierarchies
  (`interface <Domain>Exception extends Throwable`) and keep them until 1.0.

### Dependencies

- A package's `require` covers everything its `src/` imports — CI re-derives this
  (`require-check.php`); the monorepo install masking a gap is not an excuse.
- Container attributes (`#[Singleton]`, `#[Binds]`, `#[Config]`, `#[Scoped]`) are inert
  until a phpdot application reflects them: `phpdot/container` goes in `require-dev` plus a
  `suggest` entry, never in `require`, for packages that only carry attributes.
- Guarded optional integrations use `class_exists`/`extension_loaded` with FQCN references
  (no import) or a suggest-declared extension; optional phpdot bridges use
  require-dev + suggest (totp's QrCodeBridge form).

### Tests

- `final class <Thing>Test extends TestCase`, `#[Test]` attribute with descriptive camelCase
  method names (no `test` prefix), `self::assert*()` statics, `assertSame` over
  `assertEquals`. Pre-charter `it_snake_case` suites migrate opportunistically.
- `tests/Unit` and `tests/Integration` split; service-touching integration tests carry
  `#[Group('integration')]` and probe-and-skip when their service is absent (the root
  phpunit.xml fails on skips, so CI cannot silently lose them).
- Tests are style-enforced by the same fixer config as src (the vendored PSR-7 suite in
  `http/tests/Psr7` is excluded and keeps its upstream style).

## Releases

How PHPdot versions and ships. The release job in `.github/workflows/ci.yml` enforces the
mechanical parts of this policy; this section is the source it cites.

### Tag flow

Releases are cut by pushing a `vX.Y.Z` tag on the **monorepo**, on a commit in `main`'s
history. CI then tags each package **mirror** with the same version at its subtree-split sha.
One version number spans the whole framework — there are no per-package version numbers.

- A **minor** tag (`vX.Y.0`) tags **every** package, changed or not: the framework moves as
  one set, and a consumer on `^0.Y` gets a coherent line.
- A **patch** tag (`vX.Y.Z`, Z > 0) tags **only the packages changed** since the previous
  tag — unchanged mirrors keep their last tag, and Composer resolves the mix.

Published mirror tags are **immutable**: re-running a release job with the same split shas is
an idempotent no-op; a same-name tag at a different sha aborts the whole release before any
mirror is written.

### Cross-package constraints

Every `phpdot/*` requirement in every package reads the current minor line — `^0.Y` during
major zero — and all of them are bumped **together** as part of cutting a minor. This is
enforced: the release job refuses to tag while any manifest still carries the previous line.
(Caret narrows to the minor below 1.0, which is why the bump is per-minor now; from 1.0 the
constraints become `^X.0` and only bump per major.)

Cutting `v0.(Y+1).0` therefore means one commit that bumps every `phpdot/*` constraint from
`^0.Y` to `^0.(Y+1)`, then the tag.

### What a release may break (0.x policy)

- A **patch** (`v0.Y.Z`) must not break backward compatibility: bug fixes, doc fixes,
  additive internals. A consumer on `^0.Y` must be able to take every patch blindly.
- A **minor** (`v0.Y.0`) may break backward compatibility — renamed classes, moved
  interfaces, removed methods — because caret pins consumers to the minor line: nobody is
  upgraded across a 0.x minor without asking for it. Breaking changes are listed in the
  release notes of the tag.
- From **1.0.0**, the standard semver contract applies: breaks only in majors, deprecations
  announced with `@deprecated` (pointing at the replacement) at least one minor before
  removal.

### Deprecation practice

Below 1.0, an API scheduled for removal in the next minor gets `@deprecated` with a pointer
to its replacement when a same-line patch still ships it; there is no runtime deprecation
layer. `@internal` marks symbols outside the BC promise entirely — they may change in any
release.
